# NovaCRM V1.1 代码审查与补全报告

审查基线：`NovaCRM_V1.0_Full_Project.zip`（提交 `导入 NovaCRM V1.0 原始项目代码（基线）`）。
对照依据：三张原型图（工作台高保真图、12 模块总览、16 模块总览含登录/表单/移动端/部署）。

## 一、审查发现的问题及处理

| # | 级别 | 问题 | 处理 |
|---|---|---|---|
| 1 | 高 | CSP 为 `style-src 'self'`，但前端大量使用内联 `style="height:…"`，浏览器会拦截 → 工作台阶段柱状图全部失效（V1.0 无浏览器验收，未发现） | 前端全部改为 SVG 属性 / CSS 类 / `<progress>`、`<meter>`，零内联样式；已用 Chromium 验证无 CSP 报错 |
| 2 | 高 | Origin 校验仅比对单个 `PUBLIC_ORIGIN`；Compose 默认 `http://localhost:3100`，用 `127.0.0.1:3100` 访问时登录等所有写操作 403 | 允许 `PUBLIC_ORIGIN`（可逗号分隔多个）或与 Host 同源；跨站仍拒绝（有测试） |
| 3 | 高 | 登录无防爆破 | 同账号 15 分钟失败 5 次、同 IP 30 次即 429 |
| 4 | 中 | CSV 导出存在公式注入（`=HYPERLINK(...)` 等），表头为英文字段、关联字段为 UUID | 以 `= + - @` 开头的单元格加 `'`；中文表头；客户/合同/商机 ID 解析为名称 |
| 5 | 中 | 删除被合同引用的商机会留下悬挂引用；有回款计划的合同可删除 | 增加关联检查（409） |
| 6 | 中 | 销售角色可直接把合同状态改为“已签署”，无审批 | 新增提交审批 / 审批通过 / 驳回接口；非经理不得设置审批后状态，不得改已审批合同的金额与客户 |
| 7 | 中 | 枚举字段（商机阶段、任务状态、合同状态）服务端不校验，可写入任意值 | 服务端枚举校验；V1.0 旧值（初步接洽/谈判签约/待办/完成/已签署…）入参自动归一化，启动时迁移存量数据 |
| 8 | 中 | 会话表过期记录永不清理 | 启动及每小时清理 |
| 9 | 中 | 成员无法停用/改角色/重置密码；所有角色可读取全体成员邮箱 | 新增 `PATCH /api/users/:id`（防止停用自己/最后一名管理员，变更后注销会话）；非经理只返回姓名/部门/角色 |
| 10 | 低 | 工作台“在跟进线索”包含已转化线索；合同金额包含草稿/作废 | 统计口径修正 |
| 11 | 低 | PATCH 返回旧的 `updatedAt`；请求体超限后仍继续解析 | 修正 |
| 12 | 低 | 线索转化可手工把状态改为“已转化”而无关联客户 | 校验拦截，仅允许通过“转客户”操作 |
| 13 | 低 | 统计以 UTC 计“本月/今天”，中国时区 0–8 点数据错位 | 统一使用服务器本地时区，Docker 默认 `TZ=Asia/Shanghai` |
| 14 | 维护性 | `server.js`、`app.js` 为单行压缩风格，难以审查 | 重写为可读代码并分区注释 |

## 四、下一步建议（按优先级）

### P0 · 上线前必须
1. **行级数据权限**：增加 `owner_id`（用户 ID 而非姓名文本）与部门字段，按“本人 / 本部门 / 全部”控制可见范围。目前负责人是姓名字符串，改名会断链，这是迁移最好趁早做的一项。
2. **HTTPS 与生产配置**：反向代理（Nginx/Caddy）+ `COOKIE_SECURE=1` + 正确 `PUBLIC_ORIGIN`；在真实 Docker 环境跑一次构建、备份、恢复演练。
3. **金额落盘改为整数分**：当前 JSON 存元，计算时转分；财务对账要求严格时应改为整数分存储并迁移。
4. **定时备份**：`npm run backup` 接入 cron/systemd timer，并保留策略（如 7 日 + 4 周）。

### P1 · 功能完善
5. **批量导入**（Excel/CSV 客户、线索），含模板下载、预校验、错误行回显。
6. **附件**（合同扫描件、方案文档，原型“相关文件”页签）与系统 Logo 上传：需本地/对象存储与大小、类型限制。
7. **对账**（原型财务模块“对账管理”）：按客户/期间生成对账单并导出。
8. **自定义字段**：在现有 JSON 存储上实现最省力——字段定义表 + 表单/列表动态渲染。
9. **消息提醒**：任务到期、审批待办、回款计划到期 → 站内通知，后续接入企业微信/钉钉/邮件。
10. **审批流可配置**：金额阈值多级审批，记录审批历史（当前仅单级 + 最后一次意见）。

### P2 · 架构演进
11. **数据量增长后的查询**：列表目前在内存中筛选分页（单租户几万条内可用）。超过此规模时，为常用筛选字段建生成列/表达式索引，或迁移至 PostgreSQL（原型第 16 项标注了“SQLite / PostgreSQL”）。
12. **前端工程化**：原型标注 React + Vite + Ant Design。当前无依赖原生实现便于离线部署；若团队要长期迭代，建议在 API 稳定后迁移，API 无需改动。
13. **可观测性**：结构化访问日志、错误告警、`/api/health` 增加数据库可写检查。
14. **安全加固**：MFA、SSO、密码复杂度与过期策略、渗透测试；多实例部署时防爆破计数需移到共享存储（目前为单进程内存）。
15. **E2E 测试进 CI**：把本次 Playwright 脚本整理为 `tests/e2e`，在 GitHub Actions 中运行。

## 七、企业微信 / 钉钉扫码登录（V1.4）

| 项 | 实现 |
|---|---|
| 企业微信 | 自建应用（CorpID / AgentId / Secret）。浏览器打开走企业微信 Web 登录页（扫码或客户端快速确认）；在企业微信客户端内打开自动走网页授权静默登录（snsapi_base）。回调后 `gettoken`（缓存，凭证失效自动刷新）→ `auth/getuserinfo` 取 userid（非企业成员只有 openid，拒绝）→ `user/get` 取姓名、邮箱、手机（无权限时忽略） |
| 钉钉 | 企业内部应用新版 OAuth2（AppKey / AppSecret / CorpId）。`login.dingtalk.com/oauth2/auth`（scope `openid corpid`）→ `userAccessToken` → `contact/users/me` 取 unionId、昵称、手机、邮箱。**校验返回的 corpId 必须与配置一致**，拒绝其他企业的钉钉账号 |
| 成员匹配 | 已绑定身份 → 邮箱 → 手机号（团队管理新增“手机号”，兼容 +86/空格/横线）→ 可选自动开通（需返回邮箱）。匹配到后自动绑定 |
| 自助绑定 | 2022 年后新建的企业微信应用通常拿不到邮箱和手机号，因此成员可先用账号密码登录，在个人菜单“绑定企业微信 / 钉钉”扫码一次，此后直接扫码登录；可自行解绑，管理员可在团队管理中解绑 |
| 安全 | state 一次性、10 分钟有效且与登录方式绑定；同一第三方账号只能绑定一个成员、一个成员每种方式只绑定一个账号；保存配置时实时向平台校验凭证；Secret 不回传前端；“强制使用第三方登录”对三种方式统一生效（管理员保留密码登录） |
| 测试 | 模拟企业微信与钉钉开放平台接口：配置校验、授权地址（浏览器/客户端内）、邮箱/绑定/手机号匹配、凭证缓存与过期刷新、非成员、无效 code、他企账号、用户取消授权、自助绑定与冲突、自动开通、强制模式；浏览器 E2E 覆盖扫码往返与个人菜单绑定 |

**钉钉客户端内免登（V1.5）**：在钉钉 App（含 PC 客户端）工作台中打开时，登录页自动调用 JSAPI `runtime.permission.requestAuthCode` 取得免登授权码，服务端经 `gettoken`（应用凭证缓存与过期刷新）→ `topapi/v2/user/getuserinfo` → `topapi/v2/user/get` 识别成员；与扫码登录共用 unionId 绑定和匹配规则。钉钉 JSAPI 以 MIT 许可的 `dingtalk-jsapi` 按需精简打包为同源静态文件（`public/vendor/dingtalk-lite.js`，44KB，无 eval，满足严格 CSP），仅在钉钉 UA 下加载；主动退出后不自动重新登录，可点“钉钉免登”重试；失败时提示原因并保留账号密码登录。

**未做/需注意**：未与真实企业微信、钉钉租户联调（接口按官方文档实现，地址可通过 `WECOM_API_BASE`、`DINGTALK_OAPI_BASE` 等环境变量覆盖）；钉钉免登的浏览器测试使用模拟容器（UA + JSAPI 桩），真实原生桥需在钉钉 App 内验证；企业微信需在应用中配置授权回调域与可信域名，钉钉需配置重定向 URL 与应用首页地址，地址见系统设置。

## 八、安全自查（V1.6）

逐类检查：未登录访问、角色写权限、数据范围（列表/详情/统计/搜索/导出/附件/对账/通知）、多租户过滤、XSS（前端所有插入 HTML 的用户数据）、CSV/Excel 公式注入、路径穿越、上传类型与大小、开放重定向、CSRF、会话管理、敏感配置回显、邮件头注入。

| 发现 | 级别 | 处理 |
|---|---|---|
| 第三方登录 state 未与浏览器绑定：攻击者可用自己的账号发起“绑定企业微信/钉钉”，把授权链接发给他人，使对方身份绑定到攻击者账号（或把对方登录进攻击者账号） | 中 | 发起时写入短期 HttpOnly Cookie（Path=/api/sso），回调必须一致，OIDC/企业微信/钉钉均适用；新增攻击场景测试 |
| 数据范围为“本部门”的经理仍可在审计日志、工作台动态看到全公司操作 | 低 | 按数据范围过滤 |
| 登录时账号不存在则不计算密码散列，可通过响应时间判断账号是否存在 | 低 | 不存在时计算一次假散列 |
| 邮件头未清除换行 | 加固 | 统一清除 CR/LF（当前无可利用路径） |
| （此前已修）超限上传导致进程崩溃 | 高 | V1.3 已修复并有回归测试 |

XSS：前端所有用户数据经 `esc()` 转义或以 `textContent` 输出，未发现遗漏；CSP 禁止内联脚本与样式，作为第二道防线。

## 九、个人工作通知（V1.6）

审批待办、审批结果、分配负责人、每日待办摘要可推送为企业微信应用消息（文本卡片）/ 钉钉工作通知（ActionCard），按成员绑定的账号发送，可分别按事件开关，成员可在个人菜单关闭。点击通知中的链接进入系统后，登录完成会直接回到对应页面（仅允许站内路由）；在企业微信、钉钉客户端内打开会自动免登。钉钉工作通知需在设置中填写应用 AgentId。

## 十、SMTP 加密通道测试与文档更新

V1.3 遗留的“TLS 通道未在测试中覆盖”已补齐：`tests/smtp-tls.test.js` 在测试时用 openssl 临时生成证书（不入库私钥），启动支持隐式 TLS 与 STARTTLS 的假 SMTP 服务器，验证：

| 场景 | 预期 |
|---|---|
| SSL（465） | 全部命令经 TLS 发送，认证并投递成功 |
| STARTTLS（587） | 升级前只发送 EHLO 与 STARTTLS；升级后重新 EHLO，再认证、投递 |
| 服务器未提供 STARTTLS（模拟被中间人剥离） | 拒绝继续，不以明文发送凭证或邮件 |
| 自签名 / 不受信任证书、主机名不符 | 两种模式均拒绝，不发送凭证 |

反向验证：临时关闭证书校验时“不受信任证书”用例失败，去掉 STARTTLS 检查时“降级”用例失败。`lib/smtp.js` 新增可选 `ca` 参数；运行中的服务使用企业内部 CA 时，通过 `NODE_EXTRA_CA_CERTS` 配置（见 DEPLOY）。
